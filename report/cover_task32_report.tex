\begin{abstract}
This report presents the design and simulation of a comprehensive data-sharing
framework for cooperative UAV networks in emergency response scenarios, developed
under Task 3.2 of the COVER project.  The framework integrates five tightly coupled
components: (i)~a blockchain-based security layer using Proof-of-Authority (PoA)
consensus to defend against Sybil, Byzantine, and free-rider attacks;
(ii)~a Stackelberg game-theoretic incentive mechanism with Proof-of-Resource-Sharing
(PoRS) that elicits truthful participation from heterogeneous UAV agents;
(iii)~Differentially Private Stochastic Gradient Descent (DP-SGD) with tight Rényi
Differential Privacy (RDP) accounting for gradient privacy;
(iv)~Federated Learning (FL) with convergence analysis under 3D UAV mobility and
bandwidth-limited wireless channels; and (v)~a \emph{Multi-Agent Reinforcement
Learning (MARL) agentic framework} in which each UAV independently learns an
adaptive participation policy via Deep Q-Networks (DQN), with Q-network weights
periodically federated across agents.  All components are implemented in a Python
simulation framework with round-robin multi-GPU support; results in this report
were run on a single NVIDIA GB10 (Grace Blackwell, DGX Spark-class, unified
memory), with DP-SGD accelerated via vectorised per-sample gradients
(\texttt{torch.func.vmap}).  Evaluation uses CIFAR-10 as a standard FL benchmark
and AIDER (real UAV disaster imagery) as an on-task proxy; EuroSAT is wired in
(Section~7) but not yet evaluated.
\end{abstract}

\section{Introduction}
%----------------------------------------------------------------------

The COVER project (Cooperative and Intelligent Unmanned Aerial Vehicles for
Emergency Response Applications) aims to develop intelligent, connected UAV
networks capable of supporting first responders in extreme-weather events such as
flooding, wildfires, and earthquakes.  Funded under the Marie Sk\l{}odowska-Curie
Actions Staff Exchanges programme (Grant 101086228), the project runs from
January~2023 to December~2026 with a consortium led by Technische Universiteit
Eindhoven and including Georg-August-Universit\"at G\"ottingen (UGOE, Task 3.2 lead),
CentraleSupelec, KTH, and twelve associated institutions.

Task~3.2 addresses the \emph{data sharing layer}: the mechanisms by which UAVs
collaborate, share sensed data and learned models, while simultaneously maintaining
security against adversaries, protecting the privacy of raw observations, and
providing economic incentives for voluntary resource contribution.

This document describes the methodology, system model, and simulation framework
developed by the author at Northumbria University in the context of Task~3.2,
led by UGOE within the COVER consortium.

\section{System Model}
%----------------------------------------------------------------------

\subsection{UAV Network Topology}

We consider $N = 20$ UAVs deployed in a $1000 \times 1000 \times [50,\,200]$~m
three-dimensional operational area.  UAV positions evolve according to the
\emph{3D Random Waypoint Mobility Model}: each UAV selects a waypoint uniformly at
random within the volume, flies at speed $v \sim \mathcal{U}(1, v_{\max})$ with
$v_{\max} = 15$~m/s, pauses for $t_p = 5$~s upon arrival, then repeats.
UAV~0 acts as the parameter server (PS); UAVs~$1,\ldots,N-1$ are worker nodes.

\subsection{Wireless Channel Model}

Air-to-air (A2A) links follow a free-space path loss model with Rician fading:
\begin{equation}
  \mathrm{SNR}_{ij} = P_{\text{tx}} - \mathrm{FSPL}(d_{ij}) + G_{\text{Rician}},
  \label{eq:snr}
\end{equation}
where $\mathrm{FSPL}(d) = 20\log_{10}\!\left(\tfrac{4\pi d f}{c}\right)$,
$f = 5.8$~GHz, and the Rician power gain $G_{\text{Rician}}$ has K-factor
$K = 10$~dB, capturing the dominant line-of-sight component typical in open-sky
UAV operations \cite{alhourani2014}.  A UAV is eligible to participate in an FL
round only if $\mathrm{SNR}_{i,\text{PS}} \geq \gamma_{\min} = 5$~dB.

\section{Federated Learning with Differential Privacy (Sub-tasks C \& D)}
%----------------------------------------------------------------------

\subsection{Federated Averaging}

Global model parameters $\mathbf{w}$ are updated via FedAvg \cite{mcmahan2017}:
\begin{equation}
  \mathbf{w}^{(t+1)} = \sum_{k \in \mathcal{S}^{(t)}} \frac{n_k}{N_{\mathcal{S}}}
  \mathbf{w}_k^{(t)},
  \label{eq:fedavg}
\end{equation}
where $\mathcal{S}^{(t)}$ is the set of participating UAVs in round~$t$,
$n_k$ is the number of local samples, and $N_{\mathcal{S}} = \sum_{k\in\mathcal{S}} n_k$.
Each selected UAV runs $E = 5$ local SGD epochs on its private dataset before
uploading the updated weights.

Data heterogeneity across UAVs is modelled via a Dirichlet distribution:
class-conditional indices are split according to
$\mathbf{p}_c \sim \mathrm{Dir}(\alpha \mathbf{1}_N)$ with $\alpha = 0.5$,
producing the non-IID local datasets that are standard in FL research.

\subsection{DP-SGD Local Training}

To prevent the PS from inferring sensitive information from individual model
updates, each participating UAV applies DP-SGD \cite{abadi2016}:

\begin{algorithm}[H]
\caption{DP-SGD at UAV $k$, round $t$}
\begin{algorithmic}[1]
\For{each local epoch $e = 1,\ldots,E$}
  \For{each mini-batch $\mathcal{B} \subset \mathcal{D}_k$}
    \For{each sample $(x_i, y_i) \in \mathcal{B}$}
      \State Compute per-sample gradient $\mathbf{g}_i \leftarrow \nabla_{\mathbf{w}} \ell(\mathbf{w}; x_i, y_i)$
      \State Clip: $\tilde{\mathbf{g}}_i \leftarrow \mathbf{g}_i \cdot \min\!\left(1,\, \tfrac{C}{\|\mathbf{g}_i\|_2}\right)$
    \EndFor
    \State Noise: $\hat{\mathbf{g}} \leftarrow \tfrac{1}{|\mathcal{B}|}\!\left(\sum_i \tilde{\mathbf{g}}_i + \mathcal{N}(\mathbf{0}, \sigma^2 C^2 \mathbf{I})\right)$
    \State Update: $\mathbf{w} \leftarrow \mathbf{w} - \eta\, \hat{\mathbf{g}}$
  \EndFor
\EndFor
\end{algorithmic}
\end{algorithm}

The clipping threshold is $C = 1.0$ and noise multiplier $\sigma = 1.1$.

\subsection{Privacy Accounting}

Privacy expenditure is tracked with the R\'enyi Differential Privacy (RDP)
accountant \cite{mironov2017,wang2019}.  For the subsampled Gaussian mechanism with
sampling rate $q$ and noise multiplier $\sigma$, the RDP guarantee at order $\alpha$
for $T$ steps is:
\begin{equation}
  \varepsilon_{\mathrm{RDP}}(\alpha) = T \cdot
  \frac{1}{\alpha-1} \log\!\left(
    \sum_{k=0}^{\alpha} \binom{\alpha}{k} q^k (1-q)^{\alpha-k}
    e^{k(k-1)/(2\sigma^2)}
  \right),
  \label{eq:rdp}
\end{equation}
which is then converted to $(\varepsilon,\delta)$-DP via \cite{balle2020}:
\begin{equation}
  \varepsilon = \varepsilon_{\mathrm{RDP}}(\alpha) +
  \frac{\log(1/\delta) + \log\frac{\alpha-1}{\alpha}}{\alpha-1} -
  \frac{1}{\alpha}.
  \label{eq:rdp2dp}
\end{equation}
Training stops automatically when $\varepsilon > 10$ (configurable privacy budget).

\section{Incentive Mechanism (Sub-task B)}
\label{sec:incentive}
%----------------------------------------------------------------------

\subsection{Stackelberg Game Formulation}

We model data sharing as a one-leader, $N$-follower Stackelberg game
\cite{yang2019,zhan2020}:

\begin{itemize}
  \item \textbf{Leader} (PS): chooses reward rate $\lambda \geq 0$ per unit effort.
  \item \textbf{Followers} (UAVs): each chooses effort $e_i \in [0, e_{\max}]$.
\end{itemize}

\noindent\textbf{UAV utility:}
\begin{equation}
  U_i(e_i;\lambda) = \lambda e_i - \frac{c_i}{2} e_i^2,
  \label{eq:uav_utility}
\end{equation}
where $c_i \sim \mathcal{U}(0.5, 3.0)$ is UAV $i$'s heterogeneous cost coefficient.

\noindent\textbf{UAV best response:}
\begin{equation}
  e_i^*(\lambda) = \min\!\left(\frac{\lambda}{c_i},\, e_{\max}\right).
  \label{eq:br}
\end{equation}

\noindent\textbf{PS utility:}
\begin{equation}
  U_s(\lambda) = \alpha \log(1 + E(\lambda)) - \lambda E(\lambda),
  \qquad E(\lambda) = \textstyle\sum_i e_i^*(\lambda),
  \label{eq:ps_utility}
\end{equation}
where $\alpha = 10$ is the PS's valuation of FL model quality.

\noindent\textbf{Stackelberg equilibrium.}
For the unconstrained case, $E(\lambda) = \lambda H$ where $H = \sum_i 1/c_i$, giving:
\begin{equation}
  \lambda^* = \frac{-1 + \sqrt{1 + 2\alpha H}}{2H}.
  \label{eq:lambda_star}
\end{equation}
When $e_{\max}$ is binding, $\lambda^*$ is found via golden-section search.
At each FL round, the PS broadcasts $\lambda^*$ and each UAV trains for
$\lceil E \cdot e_i^* \rceil$ local epochs, scaling effort to the equilibrium.

\subsection{Proof-of-Resource-Sharing (PoRS)}

To prevent reward manipulation, each participating UAV submits a PoRS proof:
\begin{equation}
  \pi_k = \bigl(
    H_{\mathrm{SHA256}}(\Delta\mathbf{w}_k),\;
    \mathrm{MerkleRoot}(\mathcal{B}_k),\;
    t_{\mathrm{compute}},\;
    B_{\mathrm{tx}}
  \bigr),
\end{equation}
comprising the gradient update hash, a Merkle root over training batches,
wall-clock compute time, and bytes transmitted.  The on-chain smart contract
verifies $\pi_k$ and assigns an effort score:
\begin{equation}
  s_k = 0.5 \cdot \min\!\left(\frac{t_{\mathrm{compute}}}{30},1\right)
       + 0.3 \cdot \min\!\left(\frac{n_k}{500},1\right)
       + 0.2 \cdot \min\!\left(\frac{B_{\mathrm{tx}}}{5\,\text{MB}},1\right).
\end{equation}
Rewards are distributed proportionally: $r_k = (s_k / \sum_j s_j) \cdot R$,
where $R = 50$ tokens is the per-round budget.

%----------------------------------------------------------------------
\section{Blockchain Security Layer (Sub-task A)}
%----------------------------------------------------------------------

\subsection{Proof-of-Authority Consensus}

Full Proof-of-Work is energy-prohibitive on battery-powered UAVs.  We employ
\emph{Proof-of-Authority} (PoA): a pre-selected set of $V = 5$ validator UAVs
(selected by initial reputation) rotates block proposal in round-robin fashion.
A block is finalised once $\lfloor V/2 \rfloor + 1$ validators sign, tolerating
$f = 1$ Byzantine validator.

Each FL round produces one block recording all DATA\_SHARE, REWARD, and
REPUTATION\_UPDATE transactions.  The hash-linked chain ensures tamper-evidence:
block $b_i$ includes $H_{\mathrm{SHA256}}(b_{i-1})$.

\subsection{Attack Models and Defences}

\paragraph{Sybil attack.}
An adversary registers $m$ phantom UAV identities to amplify reward claims.
\emph{Defence}: FoolsGold \cite{fung2018} flags pairs with cosine similarity
$> 0.95$ as Sybil clones; a minimum on-chain token stake is also required.

\paragraph{Byzantine attack.}
Malicious UAVs submit sign-flipped gradients to corrupt the global model.
\emph{Defence}: Z-score norm outlier detection plus cosine deviation from the
mean gradient; flagged updates are excluded before aggregation.  When Byzantine
fraction exceeds 20\%, \emph{coordinate-wise median} \cite{yin2018} aggregation
is recommended over FedAvg.

\paragraph{Free-rider attack.}
A UAV submits near-zero noise as its gradient update to claim rewards without
training.  \emph{Defence}: gradient norm threshold (threshold = $0.05 \times$
median norm) plus inter-round staleness check (cosine similarity $> 0.9999$).

\section{Multi-Agent Reinforcement Learning Agentic Framework}
%----------------------------------------------------------------------

\subsection{Motivation and Problem Statement}

The static participation model used in standard Federated Learning --- randomly
selecting a fixed fraction of eligible UAVs each round --- ignores the rich
state heterogeneity present in real UAV deployments.  At any given round, each
UAV possesses a distinct combination of residual battery level, wireless channel
quality, local data quality, and accumulated experience of past reward signals.
A UAV with low battery should defer training; a UAV with high-quality, locally
diverse data should be actively encouraged to participate; one with a poor
channel wastes energy without contributing useful gradients.

We model participation as a \emph{sequential decision problem under uncertainty}
and equip each UAV with a Deep Q-Network (DQN) \cite{mnih2015} that learns to map
its observed state to an optimal participation action.  The result is an
\emph{agentic FL framework} in which UAVs are fully autonomous agents whose
collective behaviour emerges from individual rational learning rather than
top-down scheduling.  Q-network weights are periodically shared across agents
via FedAvg --- a \emph{federated Q-learning} step that accelerates policy
convergence by propagating experience across the swarm.

\subsection{Markov Decision Process Formulation}

The interaction between each UAV and the FL environment is modelled as a
finite-horizon Markov Decision Process $\mathcal{M}_i = (\mathcal{S}, \mathcal{A},
\mathcal{P}, \mathcal{R}, \gamma)$.  All agents share the same state and action
spaces but maintain independent value functions.

\paragraph{State space.}
The state observed by UAV~$i$ at the start of round~$t$ is the six-dimensional
vector
\begin{equation}
  \mathbf{s}_i^{(t)} = \Bigl[
    \beta_i^{(t)},\;
    \tilde{\gamma}_i^{(t)},\;
    q_i,\;
    \tfrac{t}{T},\;
    A^{(t)},\;
    r_i^{(t-1)}
  \Bigr] \in [0,1]^6,
  \label{eq:state}
\end{equation}
where $\beta_i^{(t)} \in [0.1, 1]$ is the normalised battery level,
$\tilde{\gamma}_i^{(t)} = \mathrm{SNR}_{i}^{(t)} / 40$~dB is the normalised
channel SNR, $q_i$ is a data-quality proxy (normalised label-distribution entropy
of UAV $i$'s local dataset), $t/T$ encodes round progress, $A^{(t)} \in [0,1]$
is the most recent global test accuracy, and $r_i^{(t-1)}$ is the previous round's
reward (clipped to $[-2, 2]$ for stability).

\paragraph{Action space.}
Each agent selects the number of local training epochs from
\begin{equation}
  \mathcal{A} = \{0,\, 1,\, 3,\, 5\},
  \label{eq:actions}
\end{equation}
where action $a = 0$ means the UAV \emph{skips} the current round entirely.
Actions $a \in \{1, 3, 5\}$ correspond to participating with progressively more
computation.

\paragraph{Reward function.}
The reward signal simultaneously incentivises accuracy improvement, penalises
energy expenditure, and discourages passive free-riding:
\begin{equation}
  R_i^{(t)} = \begin{cases}
    10\,\Delta A^{(t)} \cdot \dfrac{c_i^{(t)}}{\displaystyle\sum_{j \in \mathcal{S}^{(t)}} c_j^{(t)}}
    \;-\; 0.005\,a_i & \text{if } a_i > 0, \\[6pt]
    -0.01 & \text{if } a_i = 0,
  \end{cases}
  \label{eq:reward}
\end{equation}
where $\Delta A^{(t)} = A^{(t)} - A^{(t-1)}$ is the per-round accuracy gain,
$c_i^{(t)}$ is UAV $i$'s \emph{contribution score} (cosine similarity between its
local gradient and the aggregated model, clipped to $[0,1]$), and the
denominator normalises over all participants.  The term $0.005\,a_i$ is a linear
energy cost proportional to epochs trained.  A small penalty of $-0.01$ for
skipping prevents the degenerate all-skip policy.

\paragraph{Battery dynamics.}
Battery is depleted by training and trickle-recharged each round:
\begin{equation}
  \beta_i^{(t+1)} = \mathrm{clip}\!\left(\beta_i^{(t)} - 0.02\,a_i + 0.01,\; 0.1,\; 1.0\right).
  \label{eq:battery}
\end{equation}

\subsection{Deep Q-Network Architecture}

Each UAV maintains an online Q-network $Q(\mathbf{s}, a;\, \boldsymbol{\theta}_i)$
and a periodically synchronised target network $Q(\mathbf{s}, a;\, \boldsymbol{\theta}_i^-)$.
Both are small multi-layer perceptrons:
\begin{equation}
  Q(\mathbf{s}, a;\, \boldsymbol{\theta}) =
    \mathrm{Linear}(64, |\mathcal{A}|) \circ \mathrm{ReLU} \circ
    \mathrm{Linear}(64, 64) \circ \mathrm{ReLU} \circ
    \mathrm{Linear}(|\mathbf{s}|, 64).
  \label{eq:qnet}
\end{equation}
The output layer produces one Q-value per action.

Actions are selected $\varepsilon$-greedily:
\begin{equation}
  a_i^{(t)} = \begin{cases}
    \mathrm{argmax}_{a}\, Q(\mathbf{s}_i^{(t)}, a;\, \boldsymbol{\theta}_i) &
      \text{with probability } 1 - \varepsilon^{(t)}, \\
    \mathrm{Uniform}(\mathcal{A}) & \text{with probability } \varepsilon^{(t)},
  \end{cases}
  \label{eq:eps_greedy}
\end{equation}
where $\varepsilon^{(t)} = \max\!\left(\varepsilon_{\min},\, \varepsilon_0 \cdot \delta_\varepsilon^{\,n_{\mathrm{updates}}}\right)$
decays from $\varepsilon_0 = 1.0$ to $\varepsilon_{\min} = 0.05$ with rate
$\delta_\varepsilon = 0.99$ per gradient update step.

Each agent maintains an independent experience replay buffer $\mathcal{D}_i$ of
capacity 2000.  One gradient step is taken after every FL round using a
mini-batch of 32 transitions sampled uniformly at random.  The Huber loss is used
for robust Q-value regression:
\begin{equation}
  \mathcal{L}(\boldsymbol{\theta}_i) = \mathbb{E}_{(s, a, r, s') \sim \mathcal{D}_i}
  \left[ \ell_{\delta}\!\left(
    r + \gamma \max_{a'} Q(s', a';\, \boldsymbol{\theta}_i^-)
    \;-\; Q(s, a;\, \boldsymbol{\theta}_i)
  \right) \right],
  \label{eq:huber}
\end{equation}
where $\gamma = 0.95$ is the discount factor, $\ell_\delta$ is the Huber loss,
and the target network weights $\boldsymbol{\theta}_i^-$ are copied from
$\boldsymbol{\theta}_i$ every ten DQN update steps.

\subsection{Federated Q-Learning}

Allowing each UAV to learn its Q-function entirely from its own experience is
sample-inefficient: a UAV that never had high battery during a high-accuracy round
may never learn that the corresponding (state, action) pair is valuable.
Federated Q-learning \cite{zheng2023} addresses this by periodically sharing
Q-network weights across agents.

Every $K = 10$ FL rounds, the Q-network weights of all \emph{participating}
agents in that round are averaged via FedAvg and broadcast to all agents:
\begin{equation}
  \boldsymbol{\theta}_{\mathrm{global}}^{(t)} =
  \frac{1}{|\mathcal{S}^{(t)}|}
  \sum_{i \in \mathcal{S}^{(t)}} \boldsymbol{\theta}_i^{(t)},
  \label{eq:fedQ}
\end{equation}
after which every agent sets $\boldsymbol{\theta}_i \leftarrow \boldsymbol{\theta}_{\mathrm{global}}$.
This propagates the experience of high-performing agents to the whole swarm,
analogous to the FL update on the task model, but operating on the
\emph{policy} layer rather than the feature layer.

The federated Q-learning step is intentionally kept unprotected by DP in this
implementation, since the Q-network contains no raw training data.  Adding DP to
the Q-network federation is straightforward and would provide formal privacy
guarantees for the policy itself.

\begin{algorithm}[H]
\caption{MARL-FL: One episode of $T$ rounds}
\begin{algorithmic}[1]
\State Initialise Q-networks $\boldsymbol{\theta}_i$ for all UAVs $i=1,\ldots,N$
\State Initialise FL global model $\mathbf{w}^{(0)}$; reset environment state
\For{$t = 1, \ldots, T$}
  \For{each UAV $i$ \textbf{in parallel}}
    \State Observe state $\mathbf{s}_i^{(t)}$ (battery, SNR, data quality, progress, acc, prev-reward)
    \State Select action $a_i^{(t)}$ via $\varepsilon$-greedy policy $\pi_{\boldsymbol{\theta}_i}$
  \EndFor
  \State $\mathcal{S}^{(t)} \leftarrow \{i : a_i^{(t)} > 0 \text{ and } \mathrm{SNR}_i \geq \gamma_{\min}\}$
  \State Distribute $\mathbf{w}^{(t-1)}$ to all $i \in \mathcal{S}^{(t)}$
  \For{each $i \in \mathcal{S}^{(t)}$ \textbf{in parallel (multi-GPU)}}
    \State Run DP-SGD for $a_i^{(t)}$ local epochs; apply Byzantine/free-rider attacks if adversarial
  \EndFor
  \State Filter flagged updates; aggregate $\mathbf{w}^{(t)}$ via robust aggregation rule
  \State Generate PoRS proofs; execute PoA consensus; distribute token rewards
  \State Evaluate $A^{(t)}$; broadcast to all UAVs
  \State Compute contribution scores $c_i^{(t)}$ (cosine sim to aggregated gradient)
  \For{each UAV $i$}
    \State Compute reward $R_i^{(t)}$ via \eqref{eq:reward}
    \State Observe $\mathbf{s}_i^{(t+1)}$; store $(s, a, R, s')$ in $\mathcal{D}_i$
    \State Take one DQN gradient step; update $\varepsilon$
  \EndFor
  \If{$(t \bmod K) = 0$} FedAvg Q-networks \eqref{eq:fedQ} \EndIf
\EndFor
\end{algorithmic}
\end{algorithm}

real outcome. The $\varepsilon$ figures quoted in Sections~8.4, 8.6, and 8.7
predate this fix and understate the true privacy cost of those specific
runs by a similar order of magnitude; the non-privacy-budget findings in
those sections (MARL behaviour, the MobileNetV2 and AIDER convergence
diagnoses) do not depend on the accountant and are unaffected, since the
noise physically added during training was always drawn using the
configured $\sigma$ directly, never derived from the accountant --- only
the \emph{reported} $\varepsilon$ was wrong, not what was actually run.
\end{quote}

\subsection{Convergence Under Differential Privacy}

The simulation tracks test accuracy and cumulative privacy budget $\varepsilon$
per FL round. With the corrected accountant, 20 UAVs (channel-eligibility
limits active participants to 11/20 per round under $\gamma_{\min}=5$~dB), and
$C = 1.0$ gradient clipping, keeping a 200-round run within
$\varepsilon_{\max}=10$ requires $\sigma = 6.6$ --- roughly $6\times$ the
noise used (and misreported as fitting the same budget) before the fix.
At this noise level the model does not learn: final test accuracy is
\textbf{9.98\%}, against a 10\% chance baseline for CIFAR-10's ten classes.
Accuracy oscillates in a narrow band (7.6--13.1\%, mean 10.3\%, s.d.\ 1.2\%)
for the entire run with no upward trend --- noise around the chance level,
not a plateau reached after real learning, and nowhere near the 65\% target
(\texttt{convergence\_round} is unset). Final $\varepsilon = 5.88$, within
budget. Section~\ref{sec:dpfl-comparison} compares this outcome to published
DP-FL benchmarks and discusses why: those benchmarks were never subject to
this accounting error and were tuned for their own (correctly-accounted)
privacy budgets, which is a materially different exercise from what this
run demonstrates.

\subsection{Incentive Mechanism Convergence}

The optimal reward rate $\lambda^*$ from \eqref{eq:lambda_star} is recomputed each
round as UAV cost coefficients $c_i$ are revealed through participation.  The
total effort $E(\lambda^*) = \lambda^* H$ increases with the number of participants,
confirming that the mechanism is \emph{participation-encouraging}: more UAVs joining
raises $H$ and thus $\lambda^*$, incentivising further participation.

\subsection{Blockchain Performance}

Each FL round produces one on-chain block.  Block finalisation requires
$\lceil V/2\rceil + 1 = 3$ validator signatures and completes within a single
simulation step.  Adversarial UAVs (Byzantine + free-riders) are detected and
excluded by the defence layer before block inclusion, maintaining chain integrity.

Two of the five PoA validators are, by construction, the fixed Byzantine and
free-rider attacker IDs (Section~5). An initial implementation exhibited a
consensus deadlock: the round-robin proposer index only advanced on a
\emph{successful} block, and an excluded validator's local chain replica was
skipped during block appending, so once an excluded attacker-validator was
selected as proposer while behind, the same stale proposer was retried
indefinitely and the chain stalled permanently. This was fixed by (i)~rotating
the proposer selection to skip excluded validators rather than blocking on the
epoch index, and (ii)~replicating every finalised block to \emph{all} validator
chains regardless of that round's exclusion, so a temporarily-excluded
validator's ledger cannot permanently fork from the canonical chain. Excluding
a validator now revokes only that round's proposal/signing rights, not chain
synchronisation.

Figure~\ref{fig:full-sim} shows a 40-round confirmatory run with the fix
applied (20 UAVs, all layers active). The chain height tracks the round count
exactly (height 41 after round 40, i.e.\ one block per round with no stalls),
1.18 updates are blocked per round on average, and \textbf{2000 tokens} are
distributed in total rewards. Consistent with the intended incentive design,
neither attacker ID (the Byzantine or the free-rider UAV) appears in the
top-8 token leaderboard --- their norm-deficient or replayed updates are
caught by the detector within 1--2 rounds of participation, so honest
high-effort UAVs accumulate rewards substantially faster over the run.

\subsection{MARL Agentic Framework Results}

The MARL simulation is run via \texttt{python main.py --marl} and results are
saved to \texttt{results/marl/marl\_results.json} with a four-panel PDF plot.
Key observations from the 30-round simulation are as follows.

The results below use a corrected $\varepsilon$-greedy exploration schedule.
The original run left the DQN's exploration rate ($\varepsilon$-greedy, not to
be confused with the DP privacy budget $\varepsilon$) fixed at $1.0$ for all
30 rounds: \texttt{update()} only performs a gradient step (and only then
decays $\varepsilon$-greedy) once each agent's replay buffer holds a full
batch, and the batch size (32) exceeded the entire 30-round run length, so no
learning or decay ever happened --- the agents were making uniformly random
decisions the whole time. We fixed this by deriving both the buffer warm-up
length and the decay rate from the configured round budget
(\texttt{marl/trainer.py}), so short runs still reach the exploration floor
by their final round instead of a decay rate tuned only for much longer runs.

\begin{figure}[H]
  \centering
  \includegraphics[width=\linewidth]{marl_results.pdf}
  \caption{%
    MARL + Federated Learning simulation results over 30 communication rounds
    (20 UAVs, all layers active), post-fix.
    \textbf{Top-left}: Global test accuracy trajectory under DP-SGD ($\sigma=1.1$),
    rising from 15.5\% to 35.9\% by round~30.
    \textbf{Top-right}: Mean per-UAV DQN reward; positive early and again
    around round~18--22, slightly negative once participation locks in and
    the accuracy gain $\Delta A$ falls below the energy cost.
    \textbf{Bottom-left}: Adaptive participation rate (purple) versus the static
    60\% baseline (dashed); volatile (15--90\%) while $\varepsilon$-greedy is
    high, then locks to 90--95\% once it drops below $\sim$0.15 around round~21.
    \textbf{Bottom-right}: Cumulative privacy budget consumption (DP-$\varepsilon$),
    reaching 3.30 after 30 rounds, well within the $\varepsilon_{\max}=10$ limit.
  }
  \label{fig:marl_results}
\end{figure}

\paragraph{Accuracy convergence.}
Over 30 communication rounds the global model accuracy rises from $15.5\%$
(round~1) to $35.9\%$ (round~30, also the run's peak) under DP-SGD with
$\sigma = 1.1$. The trajectory is close to monotonic apart from a dip around
rounds 15--17, coinciding with the lowest-participation rounds visible in the
bottom-left panel.

\paragraph{Reward signal.}
Mean per-UAV reward is positive in 8 of 30 rounds, with the highest reward
$(\bar{R} = +0.064)$ occurring in round~1, when the accuracy gain $\Delta A$
from the uninitialised model is largest. Reward is also positive for several
rounds around round~18--22, as $\varepsilon$-greedy crosses into the
exploitation-dominant regime and participation recovers from its round-16
trough. From round~23 onward, with participation locked near 95\%, reward is
consistently slightly negative: $\Delta A$ has shrunk as accuracy plateaus
(Section~8.1's plateau is visible here too), so the fixed per-epoch energy
cost $0.005\,a_i$ dominates. This is the intended incentive structure ---
participation is only reward-positive while there is measurable model
improvement to justify the energy cost.

\paragraph{Adaptive vs.\ static participation.}
Participation is volatile while $\varepsilon$-greedy is high (15--90\% across
rounds 5--20, including a trough of 15\% at round~16), reflecting genuinely
exploratory --- effectively random --- action selection during that phase.
Once $\varepsilon$-greedy drops below $\sim$0.15 around round~21, participation
locks to 90--95\% and stays there through round~30: with the exploration floor
reached, the learned policy consistently favours participating. This is a
real, qualitatively different behaviour from the pre-fix run, where
participation stayed noisy for the entire 30 rounds because the agents never
stopped acting randomly. The residual round-to-round variance in the locked
phase (90 vs.\ 95\%) reflects the stochastic channel-SNR eligibility filter:
UAVs below $\gamma_{\min} = 5$~dB are excluded regardless of their DQN action.

\paragraph{Federated Q-learning.}
Q-network weights are federated at rounds 10, 20, and 30. With the corrected
warm-up (buffer fills at round~8 for this 30-round run, versus never filling
under the original fixed batch size of 32), each agent has taken several
gradient steps by the first federation event at round~10, and considerably
more by rounds 20 and 30 --- consistent with the participation policy
visibly firming up into a consistent behaviour shortly after $\varepsilon$-greedy
crosses below $\sim$0.15, rather than staying close to random for the whole run.

\paragraph{Privacy budget.}
\emph{(These $\varepsilon$ figures predate the accounting fix described at
the start of Section~8 and understate the true privacy cost by roughly the
same order of magnitude found there; the participation/reward findings
above do not depend on them.)} The cumulative DP-$\varepsilon$ grows from
1.47 after round~1 to 3.30 after round~30, well within the configured budget
of $\varepsilon_{\max} = 10$. The
growth rate visibly slows during the low-participation rounds (13--17) and
steepens once participation locks near 95\% post-round~21, confirming that
the MARL-driven participation variability translates directly into a variable
privacy expenditure rate --- a property unavailable in static FL scheduling.

\subsection{Comparison to Published DP-FL Results on CIFAR-10}
\label{sec:dpfl-comparison}

Table~\ref{tab:dpfl-comparison} places the corrected \textbf{9.98\%} accuracy
from Section~8.1 against client-level DP-FL results on CIFAR-10 reported in
two recent papers, reading the exact figures directly from their results
tables rather than from a secondary summary. The gap is now large, and for a
specific, identified reason rather than the modest capacity/scale
differences this section originally proposed.

    \bottomrule

Hybrid local/global-DP schemes, e.g.\ Khalaf et al.~\cite{khalaf2024}, report
retaining accuracy much closer to a non-private baseline, but under a weaker
DP threat model than the client-level guarantees compared in
Table~\ref{tab:dpfl-comparison}; we omit a specific figure here since we were
unable to independently verify one against the primary source at the time of
writing, and note it only as a qualitatively different approach worth
tracking rather than a directly comparable number.

The dominant factor is the one identified in Section~8.1: reaching this
framework's UAV-scale cohort (11 active clients/round) through a genuine
$\varepsilon\le10$ budget over 200 rounds requires $\sigma=6.6$, noise high
enough to erase the learning signal entirely. We cannot directly attribute
the published papers' higher accuracy to a specific $\sigma$ they used,
since their tables (like ours previously) report accuracy at a setting
rather than the exact noise level achieving it --- but their much larger
client pools (DP-FedSAM: 500 vs.\ our 11/round) mechanically permit a
smaller effective per-round noise contribution for the same target
$\varepsilon$, since DP-FedAvg-style noise is added once per round and
divided by the participant count (Section~8.6 already used this relation
for the adaptive-clipping scoping work). Two secondary factors, unchanged
from the original analysis, remain real but are no longer the primary story:

\begin{enumerate}
  \item \textbf{Model capacity.} \texttt{SimpleCNN} is a deliberately lightweight
  proxy model; DP-FedSAM's CIFAR-10 results use a ResNet-18 backbone, and
  DP-FedPGN's use GNResNet-10 --- both an order of magnitude more parameters.
  \item \textbf{Client pool size and communication budget.} DP-FedSAM trains
  300 rounds over a pool of 500 clients; this framework trains 200 rounds
  over 20 UAVs with only 11 channel-eligible per round
  ($\gamma_{\min}=5$~dB, Section~8.1) --- an order of magnitude fewer clients
  contributing gradient signal per round, on a smaller and more non-IID
  effective cohort, on top of fewer rounds overall.
\end{enumerate}

(The pipeline already applies standard CIFAR-10 augmentation --- random crop
with 4px padding and horizontal flip, in \texttt{data/partition.py} --- so
that is not a contributing factor.)

\paragraph{Backbone choice under UAV hardware constraints.} Whether the
higher-accuracy backbones above are actually flyable is a separate question
from whether they exist in the literature. VGG-16 (138M parameters,
$\approx$528~MB in fp32) is impractical to train \emph{onboard} a UAV: DP-SGD's
per-sample gradient computation (the \texttt{vmap}-fused kernel used in this
framework, Section~7) requires memory proportional to
$\text{batch\_size}\times\text{parameter\_count}$, which compounds an
already-large model's footprint on a battery- and thermally-constrained
companion computer. ResNet-18/34 (11--21M parameters) is trainable on a
capable UAV companion computer (e.g.\ Jetson Xavier NX/Orin-class hardware) but
remains 5--10$\times$ heavier than \texttt{SimpleCNN}, and the added
compute/energy draw would need to be reflected in the incentive layer's
per-epoch cost terms and the MARL reward's energy penalty
(Section~6), not merely swapped in as a drop-in replacement. A mobile-optimised
backbone --- MobileNetV2/V3 or EfficientNet-Lite~\cite{sandler2018}, using
depthwise-separable convolutions to hold parameter counts in the 2--5M range
--- was identified as the realistic middle ground on compute/energy grounds
alone. We implemented and validated it (Section~8.6); the result is a
cautionary one, not the accuracy improvement this paragraph originally
anticipated.

\subsection{MobileNetV2 Validation: A Negative Result}
\label{sec:mobilenet-negative}

\texttt{MobileNetV2CIFAR} (\texttt{models/mobilenet.py}) was implemented ---
GroupNorm throughout in place of BatchNorm for the same \texttt{vmap}
per-sample-gradient compatibility reason as \texttt{SimpleCNN}
(Section~7), stem and first stage stride reduced from 2 to 1 for 32$\times$32
input, 2.24M parameters, confirmed to train correctly end-to-end through the
DP-SGD \texttt{vmap} pipeline on CUDA. A 30-round validation run (identical
config to Section~8.1 otherwise: 20 UAVs, $\sigma=1.1$, $C=1.0$) was compared
against \texttt{SimpleCNN}'s first 30 rounds from the same run family.

\begin{table}[H]
  \centering
  \caption{Test accuracy, identical DP-FL config, by backbone.}
  \label{tab:mobilenet-negative}
  \begin{tabular}{lcccc}
    \toprule
    Backbone & Round 1 & Round 10 & Round 20 & Round 30\\
    \midrule
    SimpleCNN (0.62M params) & 16.2\% & 26.9\% & 31.4\% & 33.1\%\\
    MobileNetV2CIFAR (2.24M params) & 10.0\% & 10.0\% & 9.6\% & 10.6\%\\
    \bottomrule
  \end{tabular}
\end{table}

MobileNetV2CIFAR does not learn at all under DP-FL at these hyperparameters
--- its accuracy sits at chance level (10\% on 10 classes) for the entire
run. This is not an implementation fault: the identical architecture, trained
centrally with plain SGD and \emph{no} DP noise and \emph{no} federation,
reaches 32.9\% test accuracy after only 300 minibatch steps (well under one
epoch), confirming the network learns normally once the DP noise is removed.

The cause is a dimensionality mismatch. DP-SGD adds independent Gaussian
noise, scaled by $\sigma C$, to \emph{every} parameter each step; the total
injected noise norm therefore scales with $\sqrt{\text{parameter count}}$,
while the clipped gradient signal (bounded to norm $C$) does not grow with
it. The $(\sigma=1.1,\ C=1.0)$ pair was never tuned for a 2.24M-parameter
model --- it was carried over unchanged from \texttt{SimpleCNN}'s 0.62M
parameters, roughly a $3.6\times$ increase in dimensionality the noise
budget was never recalibrated against. Concretely, at $\approx3.6\times$ more
parameters the injected noise norm is $\approx\sqrt{3.6}\approx1.9\times$
larger for the same $(\sigma, C)$, which is enough to overwhelm the signal
from this small, heavily-partitioned per-client dataset (an average of
$\sim$2500 CIFAR-10 images per UAV, before any DP effect).

This means the future-work item below is not "swap in MobileNetV2" but
specifically \emph{re-tuning $(\sigma, C)$ --- or adopting a
dimensionality-aware technique such as per-layer or adaptive clipping ---
jointly with the backbone}, and re-validating before claiming any accuracy
benefit. We report this as the honest outcome of the experiment run rather
than reverting to the untested claim: a backbone swap under this framework's
DP-SGD implementation is not a drop-in win, and assuming otherwise without
validation (as the original phrasing of this section did) would have been
exactly the kind of unverified claim we corrected in
Section~\ref{sec:dpfl-comparison}.

\subsection{Real UAV Imagery (AIDER): Integration and a Convergence Diagnosis}
\label{sec:aider}

CIFAR-10 is a standard FL benchmark but not on-task imagery; the original
future-work list called for validating on real UAV disaster imagery. FloodNet
was the dataset originally named, but its Track~1 classification labels
(``Flooded''/``Non-Flooded'') are distributed as an unlabelled Google Drive
folder with only $\sim$400 labelled images total --- impractical to fetch
automatically and too small to partition meaningfully across 20 UAVs. AIDER
(Aerial Image dataset for Emergency Response, Kyrkou \& Theocharides, 2020)
was used instead: 6433 real UAV images across five classes (fire, flooded
areas, collapsed buildings, traffic incidents, normal), hosted as a single
263~MB Zenodo archive with no download friction.

Wiring it in surfaced a real, pre-existing bug: \texttt{simulation/runner.py}
called \texttt{load\_cifar10()} directly, so the \texttt{eurosat} and
\texttt{custom} options already documented in \texttt{data/partition.py} and
the README were dead code, never actually reachable regardless of the
\texttt{data.dataset} config value. This is now fixed --- \texttt{runner.py}
calls the \texttt{load\_dataset()} dispatcher, and the model's output layer
size is inferred from the dataset (\texttt{\_num\_classes()}) rather than
hardcoded to 10, so \texttt{eurosat} and the new \texttt{aider} option are
both now actually usable, not just documented.

\paragraph{A misleading-metric finding.} AIDER's \texttt{normal} class is
68\% of the data. At the CIFAR-tuned hyperparameters (batch size 32), round~1
reported 68.1\% accuracy and the run auto-declared convergence --- but this
is an artefact, not learning: a model predicting ``normal'' for everything
scores $\approx$68\% for free. We added a balanced-accuracy metric
(\texttt{FLServer.evaluate\_balanced()}, mean per-class recall) that a
majority-class collapse cannot game, alongside the existing raw accuracy.

\paragraph{A privacy-budget finding.} AIDER's clients hold far fewer samples
than CIFAR's ($\sim$257 vs.\ $\sim$2500 average per UAV), so the same
batch size of 32 is a much higher DP-SGD sampling rate, and $\varepsilon$
reached 9.05 of the 10.0 budget after a single round --- reducing
\texttt{local\_batch\_size} to 4 brought this qualitative problem under
control (batch 32 exhausted the budget almost immediately; batch 4 did
not). The specific $\varepsilon$ figures quoted for this diagnostic run
(2.17 at round~1, growing to 4.64 by round~10) predate the accounting fix
in Section~8 and understate the true cost by roughly the same order of
magnitude documented there; the qualitative finding --- smaller batches
reduce sampling-rate-driven budget exhaustion --- is unaffected, since it
compares two runs under the \emph{same} (buggy, at the time) accounting,
not an absolute number.

\paragraph{The remaining problem.} Even with both fixes, the model does not
learn. Table~\ref{tab:aider-diagnosis} shows raw accuracy oscillating wildly
(8.6\% to 67.5\%) while balanced accuracy stays flat at 15--26\% for all 10
rounds --- essentially the 20\% chance level for 5 classes, with no upward
trend. The raw-accuracy swings are the model flipping in and out of a
majority-class collapse, not genuine progress; balanced accuracy shows there
is none.

\begin{table}[H]
  \centering
  \caption{AIDER, 10-round diagnostic (batch size 4, otherwise identical
  DP-FL config to Section~8.1).}
  \label{tab:aider-diagnosis}
  \begin{tabular}{lcccccc}
    \toprule
    Round & 1 & 3 & 5 & 7 & 9 & 10\\
    \midrule
    Raw accuracy & 8.6\% & 46.5\% & 66.4\% & 67.5\% & 67.3\% & 28.4\%\\
    Balanced accuracy & 20.8\% & 25.9\% & 19.7\% & 20.0\% & 19.8\% & 20.8\%\\
    \bottomrule
  \end{tabular}
\end{table}

This was diagnosed as a data-scarcity problem compounding with the existing
Dirichlet non-IID partitioning: with $\sim$257 images per UAV drawn from an
already-imbalanced 5-class pool, a Dirichlet($\alpha=0.5$) split across 20
clients can leave individual clients with few or zero examples of the
minority disaster classes.

\paragraph{Stratified partitioning: implemented and tested.} We verified
the diagnosis directly: at $\alpha=0.5$, \textbf{9 of 20 clients had zero
examples of at least one class}. \texttt{dirichlet\_partition()}
(\texttt{data/partition.py}) now takes a \texttt{min\_per\_class} floor that
reserves a minimum count of \emph{every} class for \emph{every} client
before the Dirichlet-skewed remainder is distributed (default~0, i.e.\ the
original behaviour, so CIFAR-10's reported results are unaffected). At
\texttt{min\_per\_class=5}, the zero-class problem is eliminated entirely:
\textbf{0 of 20 clients} are left without at least one example of every
class.

\paragraph{Result: necessary, not sufficient.} A 30-round run with the fix
applied (batch size~4, $\sigma=5.0$ --- found the same way as
Section~8.1's $\sigma=6.6$, by binary search against the corrected
accountant for a 30-round budget at AIDER's smaller per-client scale) still
does not show genuine learning: balanced accuracy is 20.3\% at round~1,
16.7\% at round~10, 17.8\% at round~20, and 21.2\% at round~30 --- flat
around the 20\% chance level for 5 classes, no trend, while raw accuracy
climbs from 7.8\% to 47.4\% over the same rounds (the same majority-class
drift balanced accuracy exists to catch, not real progress). A shorter
check at the same batch size but the \emph{original, uncorrected} noise
level ($\sigma=1.1$) did show balanced accuracy rising (23.9\%
$\to$ 26.0\% over the first 10 rounds) before the correctly-accounted
$\varepsilon$ budget was exhausted at round~10 ($\varepsilon=19.3$, almost
$2\times$ over budget) --- i.e.\ the stratification fix genuinely helps,
but not enough to survive the noise level a real $\varepsilon\le10$
guarantee requires at this cohort size.

This is the third independent line of evidence for the same conclusion as
Sections~8.1 and~8.6: at this framework's UAV-scale cohort (11--20 active
clients), a correctly-accounted DP-SGD privacy budget of $\varepsilon\le10$
requires noise that overwhelms the learning signal, regardless of backbone
(Section~8.6), dataset (this section), or now data-engineering fix
(stratified partitioning). The binding constraint is not any one of these;
it is the cohort size itself, which is precisely why Section~9's future
work leads with adaptive clipping and larger effective participation
(Section~8.5) rather than further backbone or dataset changes.

\section{Conclusion}
%----------------------------------------------------------------------

This report has presented a unified framework for Task~3.2 of the COVER project,
integrating FL, differential privacy, game-theoretic incentives, PoRS, a PoA
blockchain, and a novel MARL agentic framework into a single simulation environment.
Each UAV agent independently learns an adaptive participation policy via DQN, with
Q-networks periodically federated across the swarm.  The MARL framework replaces
static participation scheduling with emergent, state-aware behaviour that jointly
optimises accuracy, privacy cost, energy consumption, and blockchain reward.
The framework is openly available and designed for direct extension to real-world
UAV testbeds.

\paragraph{Future work.}
(i)~\textbf{Adaptive clipping and/or larger effective participation.} Three
independent experiments (Sections~8.1, 8.6, 8.7) converge on the same root
cause: at this framework's UAV-scale cohort (11--20 active clients), a
correctly-accounted $\varepsilon\le10$ DP-SGD budget requires noise that
overwhelms the learning signal, regardless of backbone, dataset, or
partitioning fixes. This is the binding constraint, and the priority item
for making any of the CIFAR-10, MobileNetV2, or AIDER results
practically useful --- via a dimensionality-aware technique such as
per-layer or adaptive clipping~\cite{andrew2021}, and/or increasing the
number of clients contributing gradient signal per round, since
DP-FedAvg-style noise is added once per round and divided by the
participant count;
(ii)~Add DP protection to the Q-network federation step for formal policy privacy;
(iii)~replace PoRS simulation with SGX-based hardware attestation for deployment;
(iv)~extend convergence analysis to 3D trajectory optimisation jointly with power
allocation (WP2 interface);
(v)~explore multi-task MARL where agents jointly optimise sensing, routing, and FL
participation in a unified policy;
(vi)~class-weighted loss for AIDER, as a complement to the stratified
partitioning already implemented (Section~8.7), once~(i) makes the noise
level survivable enough for either to be visible in the result.
